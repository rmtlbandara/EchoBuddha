## Workflow behavior

- Deploy Production uses six attempts at most to verify the exact authorized identity. Each request has a five-second deadline. Backoff is 2, 4, 8, 12 and 15 seconds after a different valid SHA or a transient response. An invalid identity record fails immediately. The verifier does not follow redirects. The workflow still requires all 15 smoke checks before the existing IndexNow step.
- Production Smoke reads GitHub's production deployment statuses with read-only credentials. An ordinary success must link to a successful deployment workflow for the exact SHA. A recovered activation must link to a committed receipt matching the deployment, SHA, original failed deployment run, Cloudflare version at 100% traffic and independent smoke evidence. The public endpoint is compared with the selected SHA after that selection.
- A newer attempt in progress can be reported as `DEPLOYMENT_TRANSITION`. A newer failed attempt with the previous verified release still live is reported as `VERIFIED_RELEASE_SERVING_AFTER_FAILED_ATTEMPT`. If the failed attempt's SHA is live, monitoring reports `ACTIVATION_NEEDS_VERIFICATION` and fails the identity check until evidence is reconciled. A reconciled SHA with passing smoke is `VERIFIED_AFTER_INITIAL_FAILURE`. The check artifact retains the expected and observed SHAs, status IDs, evidence link and probe attempts.

## Operating a recovery

Verify the active Cloudflare deployment and Worker version, compare the public release identity and rerun the complete smoke suite pinned to the authorized SHA. Preserve the failed workflow and its evidence. With owner authorization, commit a receipt under `docs/deployments/receipts/` and append a GitHub deployment status to the existing exact-SHA deployment. Use `Verified activation after initial smoke failure:` at the start of the status description, link the receipt by full commit SHA and set `auto_inactive: false`. Verify the newest status and original workflow conclusion after writing it. If activation or smoke cannot be proven, leave the failed status in place and follow the incident process.

The monitor does not require a Cloudflare credential. It checks GitHub evidence and the public SHA and can detect drift. An activation outside this deployment workflow requires separately verified evidence and does not automatically redefine the expected SHA. If evidence is missing or unsupported, the monitor fails closed. Keep the original workflow and the receipt reachable. [Rollback runbook](ROLLBACK_RUNBOOK.md)
